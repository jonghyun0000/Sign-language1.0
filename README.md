# 한국 수화 인식기 + 손 이펙트 (Korean Sign Language Recognizer & Hand Effects)

웹캠으로 손을 추적해 두 가지 일을 하는 브라우저 앱입니다.

| 모드 | 하는 일 |
| --- | --- |
| **수어 번역** | 손동작 → 한글 자모 → **완성형 한글** → 음성(TTS) |
| **손 이펙트** | 손 모양 → 이벤트 → 파티클 이펙트. **한 손은 국소, 양손은 화면 전체 필살기** |
| **수어 사전** | 인식 가능한 모든 손 모양과 뜻을 그림으로 보여주는 학습 페이지 |

**MediaPipe Hands**로 손 랜드마크 21개를 추적하고, **규칙 기반 TypeScript 분류기**로
손 모양을 판별하며, **Web Speech API**로 한국어를 읽어줍니다. 이펙트는 직접 만든
2D 파티클 엔진과 **Web Audio 합성음**으로 그립니다. 외부 이미지·음원 파일이 전혀
없어 오프라인에서도 동작합니다(최초 1회 모델 다운로드 제외).

> ## ⚠️ 먼저 읽어주세요
>
> **이 앱으로 한국 수어를 배우지 마세요.**
>
> 초기 버전은 손 모양을 제가 임의로 만들어 냈습니다. 그건 한국 지문자가
> 아니었고, 배우는 사람에게는 오히려 해로웠습니다. 이후 학술 자료를 조사해
> **실제 수형(手形) 목록**을 확보하고 전면 재작성했지만, 여전히 한계가 있습니다.
>
> | 확보한 것 | 확보하지 못한 것 |
> | --- | --- |
> | 지문자가 쓰는 수형 17종의 **정확한 정의** (자음 12 + 모음 5) | **어떤 글자가 어떤 수형을 쓰는지** 대응표 |
> | 모음은 수형이 아니라 **방향으로 구분**된다는 구조 원리 | 실제 카메라 인식률 |
>
> 그래서 25개 손 모양 중 **자료로 확인된 것은 ㅎ 하나뿐**이고, 나머지는
> 추정 또는 임시 배정입니다. 각 항목의 신뢰도를 **앱 화면에 그대로 표시**합니다.
>
> 실제 수어 학습은 [한국농아인협회](https://www.deafkorea.com)나
> [국립국어원 한국수어사전](https://sldict.korean.go.kr)을 이용해 주세요.

## 3. 자료 조사와 신뢰도 (가장 중요한 절)

### 3.1 조사로 알게 된 것

한글 지문자는 1946년 윤백원이 한글 자모 모양을 본떠 창안했습니다. 학술 자료에서
확보한 핵심 사실:

| 사실 | 이 프로젝트에 미친 영향 |
| --- | --- |
| 자음 19개가 **12개 수형**을, 모음 20개가 **단 5개 수형**을 씀 | 손 모양 종류가 적음 → 방향이 결정적 |
| 모음 9개가 **1형(검지만)** 하나를 공유 | 모음은 손 모양이 아니라 **방향으로 구분**됨 |
| 자음도 같은 수형을 방향으로 나눠 씀 (6형을 3글자가 공유) | ㄱ/ㄴ 처럼 손 모양이 같고 방향만 다른 쌍 발생 |
| ㅆ만 유일하게 **움직임**을 포함 | 정적 분류기로는 표현 불가 → 범위 밖 |

확보한 수형 정의 (손가락 번호: 1=엄지 … 5=새끼):

```
자음 12종  2형(2,3) · 6형(1,2) · 7형(1,2,3) · 4형붙임형(2~5 붙임) · 3형(2,3,4)
          2형구부림형(2,3 첫마디만) · 8형(1~4) · 7형검지구부림형(1,3 + 2 첫마디만)
          10형(1,2로 고리 + 3,4,5 폄) · 티읕형(2,3,4, 3·4 붙임) · 히읗형(1만)
          갈퀴형(2~5 첫마디만)

모음 5종   1형(2만) · 2형(2,3) · 여우형(2,5) · 제비형(2,3,5) · 여자형(5만)
```

### 3.2 확보하지 못한 것

논문의 글자↔수형 대응표는 **한글이 이미지로만 실려 있어** 텍스트로 추출할 수
없었습니다. 게다가 국내 자료끼리도 충돌합니다 — 한 자료는 ㄱ을 "엄지+새끼"로,
다른 근거는 "엄지+검지"를 가리킵니다. 확인할 방법이 없었습니다.

### 3.3 그래서 한 일 — 불확실성을 코드에 드러내기

숨기는 대신 **데이터 구조에 넣고 화면에 표시**했습니다.

| 배지 | 뜻 | 개수 |
| --- | --- | --- |
| 🟢 **자료 확인됨** | 자료에서 직접 확인 | **1개** (ㅎ — 수형 이름이 "히읗형") |
| 🟡 **추정** | 수형은 실재하나 이 글자에 대응하는지는 미확인 | 19개 |
| 🔴 **임시 배정** | 근거 없음. 학습용 사용 금지 | 5개 (ㅡ + 단어 4개) |

각 항목은 `rationale`(왜 이렇게 정했는지)과 `source`를 함께 들고 다니며,
사전 페이지의 배지에 마우스를 올리면 그대로 볼 수 있습니다.

```ts
fingerspelling({
  label: 'ㅎ',
  handshape: C.hHieut,          // 히읗형 = 1지만 폄
  confidence: 'verified',
  rationale: '수형 이름 자체가 "히읗형"이고 정의가 "1지만 완전히 폄"입니다.',
})
```

> **단어 5개(안녕하세요 등)는 수어가 아닙니다.** 실제 한국수어 단어는 움직임과
> 양손, 표정을 함께 씁니다. 정지된 손 모양 하나로는 표현할 수 없어, 이 앱만의
> 입력 단축키로 두고 전부 '임시 배정'으로 표시했습니다.

## 4. 혼동 행렬 — 규칙이 실제로 구분되는지 측정

```bash
npm run confusion
```

### 4.1 왜 만들었나

기존 테스트는 **순환논리**였습니다. 제가 만든 가상의 손이 제가 만든 규칙을
통과하는지 보는 것이라, 통과해도 실제로 잘 되는지 알 수 없었습니다.

혼동 행렬은 다릅니다. **규칙 집합 자체의 성질**을 측정합니다. ㄱ 손 모양을
만들었을 때 ㄱ 규칙이 1등인지, 2등과 점수 차이가 얼마인지 봅니다. 차이가
작으면 카메라의 미세한 떨림만으로 뒤집힙니다.

### 4.2 이 도구가 잡아낸 실제 버그

**(1) 아래를 향하는 글자가 구조적으로 인식 불가였음** — 가장 심각

손가락 폄 판정이 "손끝이 PIP보다 **손목**에서 먼가"였습니다. 그런데 손가락을
아래로 뻗으면 손끝이 손목 쪽으로 내려옵니다. 그래서 **ㅅ·ㅜ·ㅠ 는 어떻게 해도
인식되지 않았습니다.** 58개 테스트가 이걸 전혀 잡지 못했습니다.

→ **MCP(뿌리 관절) 기준**으로 바꿔 해결. 방향과 무관해졌습니다.

**(2) 갈퀴형을 표현할 수 없었음**

"폈다/접었다" 2단계로만 봐서, 첫마디만 편 갈퀴형이 "접힘"으로 읽혀 ㅁ이
아예 인식되지 않았습니다(자기 점수 0.200).

→ **굽힘 3단계**(extended / bent / curled) 도입으로 해결.

**(3) 단어가 자모 인식을 망가뜨리고 있었음**

스마트 모드가 항상 단어를 후보에 넣었는데, 도와주세요 ≡ ㅗ, 감사합니다 ≡ ㅎ,
괜찮아요 ≡ ㅇ 로 **손 모양이 완전히 동일**했습니다(점수 차이 0.000).

→ 단어는 '단어' 모드에서만 인식하도록 분리.

### 4.3 측정 결과

| 조건 | 오인식 | 아슬아슬 | 안전 |
| --- | --- | --- | --- |
| 수정 전 (카테고리 분리) | 13 / 25 | 10 | 2 |
| **수정 후 (카테고리 분리)** | **0 / 25** | 8 | 17 |
| 수정 후 + 카메라 떨림 ±0.012 | 1 / 25 | 5 | 19 |
| 전체 경쟁 (사전 모드 '전체') | 5 / 25 | 16 | 4 |

마지막 줄이 **스마트 모드가 선택이 아니라 필수인 이유**입니다.

> 이 수치는 실제 카메라 성능이 **아닙니다.** 가상의 손으로 측정한 "규칙끼리
> 얼마나 구분되는가"입니다. 실제 인식률은 반드시 카메라로 측정해야 합니다.

## 5. 수어 번역 모드

### 5.1 한글 조합 — 이 앱의 핵심

지화는 자음과 모음을 하나씩 표현합니다. 그대로 이어 붙이면 `ㄱㅏㅁㅅㅏ`처럼
읽기 어려우므로, 한글 조합 규칙을 적용해 **완성형 글자**로 만듭니다.

```
ㄱ → ㅏ → ㅁ → ㅅ → ㅏ     ⇒   "감사"
```

`src/utils/hangulComposer.ts`가 처리하는 것:

| 기능 | 예시 |
| --- | --- |
| 초성 + 중성 | ㄱ + ㅏ → 가 |
| 받침 | 가 + ㅁ → 감 |
| 받침 이동 | 각 + ㅏ → 가**가** |
| 복합 모음 | ㅗ + ㅏ → ㅘ (ㅎㅗㅏ → 화) |
| 겹받침 | ㄹ + ㄱ → ㄺ (ㄷㅏㄹㄱ → 닭) |
| 쌍자음 | ㄱ + ㄱ → ㄲ (ㄱㄱㅜㅁ → 꿈) |
| 백스페이스 | 감 → 가 → ㄱ → (빈 문자열) |

### 5.2 인식 범위(사전) — 정확도를 올리는 장치

손 모양의 가짓수는 한정적이라 자음과 모음이 겹칩니다. 후보를 좁히면 오인식이
크게 줄어듭니다.

| 모드 | 설명 |
| --- | --- |
| **스마트** (기본) | 한글 구조를 이용해 자음 → 모음 → 자음… 순으로 **자동 전환** |
| 자음 / 모음 / 단어 | 해당 종류만 인식 |
| 전체 | 모두 인식 (자유롭지만 오인식이 가장 많음) |

스마트 모드는 조합기의 `expecting` 값을 읽습니다. 초성이 입력되면 "다음은 모음"임을
알기 때문에, 그 순간 모음 후보만 검사해 ㄱ과 ㅏ의 혼동을 원천 차단합니다.

### 5.3 인식 가능한 손 모양

각 항목의 **신뢰도**를 함께 표시합니다. 🟢 확인됨 / 🟡 추정 / 🔴 임시 배정.

**자음 10개**

| 자모 | 수형 | 손 모양 | 신뢰도 |
| --- | --- | --- | --- |
| ㄱ | 6형 | 엄지+검지로 ㄱ자, 검지가 왼쪽 | 🟡 |
| ㄴ | 6형 | 엄지+검지로 ㄴ자, 검지가 오른쪽 | 🟡 |
| ㄷ | 2형 | 검지+중지를 **붙여서** 옆으로 | 🟡 |
| ㄹ | 3형 | 검지·중지·약지 | 🟡 |
| ㅁ | 갈퀴형 | 네 손가락을 갈퀴처럼 굽혀 네모 | 🟡 |
| ㅂ | 4형 붙임형 | 네 손가락을 붙여 위로 | 🟡 |
| ㅅ | 2형 | 검지+중지를 **벌려서** 아래로 | 🟡 |
| ㅇ | 10형 | 엄지+검지 고리, 나머지 셋은 폄 | 🟡 |
| ㅈ | 7형 | 엄지·검지·중지 | 🟡 |
| **ㅎ** | **히읗형** | **엄지만 위로** | 🟢 **확인됨** |

**모음 10개** — 수형은 2~3종뿐이고 **방향이 글자를 결정**합니다.

| 수형 | 방향 → 글자 | 신뢰도 |
| --- | --- | --- |
| 1형 (검지만) | 오른쪽 → **ㅏ** · 왼쪽 → **ㅓ** · 위 → **ㅗ** · 아래 → **ㅜ** | 🟡 |
| 2형 (검지+중지) | 오른쪽 → **ㅑ** · 왼쪽 → **ㅕ** · 위 → **ㅛ** · 아래 → **ㅠ** | 🟡 |
| 여자형 (새끼만) | 위 → **ㅣ** | 🟡 |
| 여우형 (검지+새끼) | 옆 → **ㅡ** | 🔴 **임시** |

> 실제 지문자는 1형 하나로 모음 9개를 표현합니다. 이 앱은 방향을 4개만
> 구분하므로 그중 4개까지만 담을 수 있습니다. 나머지는 손바닥 방향 등
> 추가 축이 필요합니다.

**단어 4개** — 🔴 전부 임시 배정. 실제 수어가 아닌 입력 단축키입니다.
안녕하세요(다섯 손가락) · 감사합니다(엄지 척) · 사랑합니다 · 도와주세요 · 괜찮아요

## 6. 손 이펙트 모드

### 6.1 핵심 규칙: 한 손 = 국소, 양 손 = 화면 전체

기억할 규칙은 딱 하나입니다.

> **같은 손 모양을 양손으로 만들면 화면 전체 필살기로 승급됩니다.**

한 손으로 주먹을 쥐면 손 주변에서 에너지가 터지지만, 양손으로 주먹을 쥐면
화면 전체가 유리처럼 갈라지고 흔들립니다. 새 손 모양을 외울 필요 없이
이펙트 규모만 커지므로 익히기 쉽습니다.

#### 한 손 (손 주변 국소 이펙트)

| 이펙트 | 손 모양 | 동작 방식 |
| --- | --- | --- |
| **거미줄 발사** | 엄지·검지·새끼 펴고 중지·약지 접기 | 손 모양을 만든 **순간 1회** 발사. 손목에서 줄기가 뻗고 끝에 스플랫이 붙음 |
| **화염 방사** | 다섯 손가락 모두 펴기 | 유지하는 **동안 계속** 분사 |
| **번개** | 검지+중지 V자 | 유지하는 동안 지그재그 번개가 번쩍임 |
| **반짝임 트레일** | 검지만 곧게 펴기 | 손끝을 따라 무지개 궤적이 남음 |
| **에너지 충격파** | 주먹 쥐었다가 **펴기** | 쥐는 동안 **충전**, 펴는 순간 충전량에 비례해 폭발 (최대 2.2초) |
| **핑거스냅** | 엄지와 중지를 펴서 맞대기 | 순간적으로 먼지가 흩날림 |

#### 양 손 (화면 전체)

| 이펙트 | 손 모양 | 연출 |
| --- | --- | --- |
| **하트** | 양손 엄지·검지를 **맞대기** | 두 손 사이에서 하트가 떠오름 |
| **거미줄 봉인** | 양손 거미줄 손 모양 | 화면 중앙에서 거대한 거미줄이 퍼져 화면 전체를 덮음 + 진동 |
| **불바다** | 양손 다섯 손가락 펴기 | 화면 **아래 전체**에서 불길이 솟구침 + 붉은 비네트 + 지속 진동 |
| **번개 폭풍** | 양손 브이(V) | 화면을 가로지르는 번개가 연달아 내리침 + 섬광 + 진동 |
| **별가루 폭풍** | 양손 검지만 펴기 | 화면 위 전체에서 무지개 별가루가 흩날려 내려옴 |
| **화면 균열** | 양손 주먹 쥐었다 **펴기** | 충전 후 화면이 **유리처럼 갈라지고** 격렬하게 흔들림 |

#### 화면 전체 연출 도구 (`ScreenEffects.ts`)

| 도구 | 하는 일 |
| --- | --- |
| `ScreenFlash` | 화면 전체가 순간적으로 번쩍임 |
| `ScreenVignette` | 화면 가장자리가 특정 색으로 물듦 (불바다의 붉은 테두리) |
| `ScreenCrack` | 화면이 유리처럼 갈라짐 — 어두운 틈 + 밝은 하이라이트를 겹쳐 그림 |
| `ScreenShaker` | **DOM 요소를 통째로 흔듦** |

> **흔들림만 캔버스가 아니라 DOM을 움직이는 이유** — 캔버스 안에서 좌표만
> 옮기면 파티클만 흔들리고 카메라 영상은 가만히 있어 어색합니다. 컨테이너
> 요소에 `transform`을 걸어야 "화면이 흔들린다"는 느낌이 납니다.

### 6.2 이벤트 기반 구조

이펙트는 "상태"가 아니라 **"변화"** 로 구동됩니다. `EffectGestureDetector`가
손 모양을 판정해 세 가지 이벤트를 발행하고, `EffectManager`가 이를 각 이펙트에
전달합니다.

```
MediaPipe → EffectGestureDetector → EventBus → EffectManager → ParticleEngine → Canvas
                                     ├─ enter  (1회)  … 거미줄 발사, 핑거스냅
                                     ├─ hold   (매 프레임) … 화염, 번개, 반짝임
                                     └─ exit   (1회)  … 에너지 방출
```

이 구조 덕분에 **새 이펙트를 추가할 때 감지 코드를 건드릴 필요가 없습니다.**

<details>
<summary>새 이펙트 추가하는 법 (3단계)</summary>

1. `src/types/index.ts`의 `EffectGestureId`에 id 추가
2. `src/effects/definitions/myEffect.ts` 작성 (`onEnter`/`onHold`/`onExit` 중 필요한 것만)
3. `src/effects/EffectManager.ts`의 `EFFECT_DEFINITIONS` 배열에 추가

손 모양 판정 규칙은 `src/services/EffectGestureDetector.ts`의 `scoreSingleHand()`에
한 줄 추가하면 됩니다. UI 안내판(`EffectLegend`)은 자동으로 갱신됩니다.
</details>

### 6.3 파티클 엔진

- 파티클 최대 **1,400개**, 죽은 파티클은 swap-remove로 제거 (splice보다 빠름)
- 모양: `circle` · `spark`(속도 방향으로 늘어남) · `heart` · `ring` · `square`
- **加算 합성**(`globalCompositeOperation = 'lighter'`)으로 겹칠수록 밝게 빛남
- 선처럼 이어진 것(거미줄, 번개)은 파티클 대신 **엔티티**로 구현
- 모든 물리 계산이 `dt` 기반이라 프레임률이 달라도 속도가 일정

### 6.4 효과음

`SoundService`가 Web Audio API로 **직접 합성**합니다 (mp3 파일 없음).

| 소리 | 합성 방식 |
| --- | --- |
| 거미줄 "츄웁" | 화이트 노이즈 + 밴드패스 3000→600 Hz 하강 |
| 번개 "지직" | 사각파 하강 + 하이패스 노이즈 |
| 반짝임 | 오음계에서 무작위로 고른 사인파 (어떤 조합도 듣기 좋음) |
| 폭발 | 저역 사인 하강 + 로우패스 노이즈 |
| 화염 | 필터를 건 노이즈 **루프** |

> 브라우저 자동재생 정책 때문에 **첫 클릭 시점**에 `AudioContext`를 활성화합니다.

## 7. 수어 사전 (학습 페이지)

세 번째 모드인 **수어 사전**은 "어떤 손 모양이 어떤 뜻인지"를 한자리에 모아
보여줍니다.

* **손 모양 그림** — 이모지가 아니라 실제 손 모양을 그린 SVG
* **뜻 / 쓰임새** — `기역. '가·구·국'의 첫소리` 처럼 언제 쓰는지 설명
* **만드는 방법** — `검지를 갈고리처럼 꺾어 옆으로`
* **분류 탭** — 전체 / 자음 / 모음 / 단어 / 이펙트
* **검색** — 자모, 뜻, 손 모양 설명 어디에서든 검색

### 연습 모드 — 사전의 핵심 기능

사전 페이지에서도 **카메라가 계속 돌아갑니다.** 손을 만들면 지금 인식되고
있는 카드가 실시간으로 보라색으로 강조되고 "인식 중" 배지가 뜹니다.
"내가 지금 제대로 하고 있나?"를 즉시 확인할 수 있어 학습 효율이 크게
올라갑니다. 이때 인식 결과는 강조에만 쓰이고 **번역 텍스트에는 들어가지
않습니다.**

> 모드를 바꿔도 카메라 컴포넌트를 언마운트하지 않습니다. 언마운트하면 카메라가
> 껐다 켜지면서 몇 초씩 멈추기 때문입니다. 대신 사전 모드에서는 카메라를 작게
> 줄여 "연습용 창"으로 씁니다.

## 8. 이모지 대신 직접 그린 그래픽

앱 전체에서 이모지를 없애고 두 가지로 교체했습니다.

### 8-1. 손 모양 그림 (`HandShape.tsx`)

이모지를 쓸 수 없던 이유:

* 🤟 하나만 해도 애플·구글·윈도우에서 손가락 각도가 제각각이라 **"정확히 이
  손 모양을 만드세요"를 전달할 수 없습니다.**
* ㅏ와 ㅓ처럼 **방향만 다른 손 모양**은 이모지로 아예 표현이 불가능합니다.
* ㄱ(꺾은 검지)과 ㅏ(곧게 편 검지)의 차이도 표현할 수 없습니다.

그래서 손 모양을 **데이터로 서술**하고 컴포넌트가 SVG를 그립니다.

```ts
// ㄱ — 검지를 갈고리처럼 꺾어 옆으로
shape: { fingers: fg(F, T, F, F, F), direction: 'right', bent: true }

// ㅏ — 검지를 곧게 펴서 오른쪽
shape: { fingers: fg(F, T, F, F, F), direction: 'right' }
```

표현할 수 있는 것: 손가락 폄/접힘, 방향 4가지(회전), 엄지와 맞댄 동그라미,
갈고리처럼 꺾인 손가락, 붙임/벌림(ㄷ vs ㅅ), 양손.

**이 데이터는 분류기 규칙 바로 옆에 있습니다.** 즉 그림과 실제 인식 규칙이
같은 파일을 공유하므로 "설명과 실제 동작이 다른" 문제가 생길 수 없습니다.

### 8-2. UI 아이콘 (`icons.tsx`)

버튼과 탭의 이모지(🔊 ⏹ ♻ ␣ ⌫ 💾)는 24×24 선 기반 SVG 아이콘으로 교체했습니다.
`currentColor`를 쓰므로 버튼 글자색에 자동으로 맞춰지고, 크기를 키워도
흐려지지 않습니다.

> 참고: 애플의 **미모티콘(Memoji)** 은 애플 독점 자산이라 웹 앱에 넣을 수
> 없습니다. 대신 같은 목적(기기와 무관하게 일관된 그래픽)을 직접 그린 SVG로
> 달성했습니다.

## 9. 좌표 정확도 (`coverFit.ts`)

`<video>`는 `object-fit: cover`로 그려지므로 컨테이너 비율이 다르면 영상 일부가
잘립니다. 하지만 랜드마크는 "잘리기 전" 영상 기준 0~1 좌표라서, 단순히
`x * canvasWidth`로 계산하면 **손 위치와 이펙트가 어긋납니다.**

`computeCoverFit()`이 cover 규칙(더 크게 확대되는 축을 따르고 가운데 정렬)을
그대로 재현해 정확히 변환합니다. 창 크기를 바꾸거나 모바일에서 회전해도
어긋나지 않습니다.

거울 처리도 여기서 합니다. `<video>`만 CSS로 좌우 반전하고, 캔버스는 반전하지
않은 채 **좌표 계산에서 x를 뒤집습니다**(`1 - x`). 캔버스를 CSS로 반전하면 그
안에 그리는 글자까지 뒤집히기 때문입니다.

## 10. 테스트 방법

### 10.1 자동 검증 (카메라 불필요)

```bash
npm run verify
```

가상의 손 좌표를 만들어 순수 로직을 검증합니다 — 총 **62개 테스트**.

손 좌표는 이제 **규칙에 선언된 손 모양에서 자동 생성**합니다. 예전처럼 좌표를
손으로 적어두면 규칙을 고칠 때마다 테스트가 낡아버리기 때문입니다.

회귀 방지 테스트도 넣었습니다 — 아래를 향하는 ㅅ·ㅜ·ㅠ 가 인식되는지 확인합니다.
이건 한때 구조적으로 불가능했던 부분이라 다시 깨지지 않도록 못을 박아 뒀습니다.

```bash
npm run confusion   # 규칙끼리 얼마나 구분되는지 (4절 참고)
```

> 이 스크립트가 실제로 버그를 잡았습니다: 검지를 펴서 가리킬 때 접힌 엄지와
> 접힌 중지가 가까워져 "핑거스냅"으로 오인식되던 문제입니다. 이제 스냅은
> **두 손가락이 모두 펴진 상태**를 함께 확인합니다.

### 10.2 수동 확인 (카메라 필요)

1. `npm run dev` → `http://localhost:5173`
2. **권한 확인** — 카메라 권한을 한 번 거부해 보세요. "카메라 권한이 거부되었습니다…"
   오류 배너가 떠야 합니다.
3. **손 추적** — 한 손을 보여주면 파란 뼈대와 빨간 관절 점이 겹쳐 보여야 합니다.
4. **손 없음 상태** — 손을 내리면 "현재 인식"이 ✋ 와 "손을 카메라 앞에 보여주세요"로 바뀝니다.
5. **자음 인식** — 주먹을 쥐면 "ㅁ"이 뜨고 신뢰도가 70 % 이상으로 올라간 뒤
   오른쪽 패널에 "ㅁ"이 추가됩니다.
6. **중복 방지** — 주먹을 계속 쥐고 있어도 약 1.2초 동안은 더 추가되지 않아야 합니다.
7. **한글 조합** ★ — 주먹(ㅁ) → 검지 오른쪽(ㅏ) 순서로 하면 "마"로 **합쳐져야** 합니다.
8. **스마트 모드** — 자음을 입력한 뒤 배지가 "지금 기다리는 것: 모음"으로 바뀌는지 확인.
9. **말하기** — "🔊 말하기"를 누르면 한국어 음성이 나옵니다. "⏹ 중지"로 즉시 멈춥니다.
10. **저장/기록** — "💾 저장" 후 아래 기록에 남고, 새로고침해도 유지되어야 합니다.
11. **이펙트 모드** — 🤟 모양을 만들면 손목에서 거미줄이 발사되고 "츄웁" 소리가 납니다.
12. **에너지 충전** — 주먹을 2초쯤 쥐고 있다가 펴면 큰 충격파가 터집니다.
13. **양손 하트** — 양손 엄지·검지를 맞대면 하트가 떠오릅니다.
14. **화면 전체 필살기** ★ — 양손 모두 다섯 손가락을 펴면 화면 아래 전체에서
    불길이 솟구치고 테두리가 붉어지며 화면이 미세하게 떨려야 합니다.
15. **화면 균열** ★ — 양손 주먹을 2초쯤 쥐었다가 동시에 펴면 화면이 유리처럼
    갈라지고 격렬하게 흔들려야 합니다.
16. **수어 사전** — 세 번째 탭을 열면 37개 카드(수어 25 + 이펙트 12)가 손 모양
    그림과 함께 보여야 합니다. 검색과 분류 탭이 동작하는지 확인하세요.
17. **연습 모드** ★ — 사전 페이지에서 주먹을 쥐면 "ㅁ" 카드가 보라색으로
    강조되고 "인식 중" 배지가 떠야 합니다. 이때 번역 텍스트에는 아무것도
    들어가지 않아야 합니다.
18. **이모지 확인** — 화면 어디에도 이모지가 없어야 합니다. 모든 아이콘이
    선으로 그려진 SVG이고, 손 모양은 손가락이 그려진 그림이어야 합니다.
19. **반응형** — 창을 좁히면 세로로 쌓이고, 이펙트 좌표가 여전히 손에 붙어 있어야 합니다.

## 11. 향후 개선 방향

### P0 — 이게 없으면 "수어 앱"이라 부르면 안 됨

1. **글자↔수형 대응표 확보** — 『한국수화사전』(2005) 실물이나 국립국어원
   한국수어사전 이미지를 직접 확인해야 합니다. 웹 텍스트로는 한계에 부딪혔습니다.
2. **실제 카메라 측정** — 각 글자를 20회씩 시도해 인식률을 기록. 지금은
   실사용 성능을 전혀 모릅니다.
3. **농인 또는 수어 통역사 검토** — 코드로 해결할 수 없는 부분입니다.

### P1 — 기술적 개선

- **학습 모델 전환** — 규칙 기반은 한계가 명확합니다
  1. 사용자가 각 손 모양을 취하면 랜드마크를 라벨과 함께 기록하는 **캘리브레이션 모드** 추가
  2. 21×3 랜드마크 벡터로 작은 **TensorFlow.js** MLP 학습 (64 유닛 은닉층 + softmax면 30클래스 정도는 충분)
  3. `GestureClassifier`의 `classifyHand` 호출부만 교체 — 안정화·중복 방지 계층은 그대로 재사용
- **문장 단위 수어 인식** — 한국수어는 움직임이 핵심입니다. 30프레임 정도의 슬라이딩
  윈도우에 LSTM/Transformer를 얹으면 동작이 포함된 단어를 인식할 수 있습니다.
- **양손 제스처 확장** — 현재 번역 모드는 `hands[0]`만 씁니다. 많은 수어가 비주도손을
  받침대처럼 쓰므로, 두 손과 `handedness`를 함께 규칙에 넘기면 표현력이 크게 늘어납니다.
- **사용자 캘리브레이션** — 손 비율은 사람마다 다릅니다. 기준 프레임 몇 장을 녹화해
  임계값을 개인화하면 정확도가 올라갑니다.
- **모바일 지원 강화** — `playsInline`은 이미 적용했습니다. iOS Safari 실기 테스트와
  전/후면 카메라 토글을 추가하면 좋습니다.
- **수어 애니메이션 역변환** — 한국어 텍스트를 입력하면 3D 아바타가 수어로 표현하도록
  하면, 청인이 수어를 배우는 데도 쓸 수 있습니다.
- **다국어 UI** — 한국어 문자열을 i18n 번들로 분리해 한/영 전환 지원.
- **이펙트 확장** — 순간이동, 검기, 물결 등. 6.3절의 3단계만 따르면 됩니다.
- **사전에 동영상 추가** — 지금은 정지된 손 모양 그림만 있습니다. 실제 사람이
  수어를 하는 짧은 영상을 카드에 넣으면 움직임이 있는 수어도 배울 수 있습니다.
- **연습 채점** — 연습 모드에서 "정확도 몇 %"나 "이 손가락을 더 펴세요" 같은
  구체적인 피드백을 주면 학습 효과가 더 커집니다.

## 12. 기술 스택

| 영역 | 선택 |
| --- | --- |
| 프레임워크 | React 18 + Vite + TypeScript (strict) |
| 손 추적 | `@mediapipe/tasks-vision` (HandLandmarker, GPU delegate) |
| 분류 | 규칙 기반 TypeScript (향후 TF.js) |
| 이펙트 | 자체 제작 2D 파티클 엔진 (Canvas 2D) + 화면 전체 연출 |
| 아이콘·손 그림 | 직접 그린 SVG (이모지 미사용) |
| 음성 출력 | Web Speech API (`ko-KR`) |
| 효과음 | Web Audio API 실시간 합성 (외부 파일 없음) |
| 저장소 | localStorage |
| 스타일 | 직접 작성한 CSS (UI 라이브러리 없음) |
| 검증 | `tsc --noEmit` + `scripts/verify.ts` |

**런타임 의존성은 3개뿐입니다**: `react`, `react-dom`, `@mediapipe/tasks-vision`.

## 13. 알려진 한계

### 가장 큰 한계 — 아직 검증되지 않았습니다

| 항목 | 상태 |
| --- | --- |
| 글자↔수형 대응표 | ❌ 미확보. 25개 중 24개가 추정/임시 |
| 실제 카메라 인식률 | ❌ **한 번도 측정 안 함** |
| 농인·수어 통역사 검토 | ❌ 없음 |
| 조명·각도·손 크기 다양성 | ❌ 테스트 안 함 |
| 모바일 실기 | ❌ 테스트 안 함 |

혼동 행렬 수치(오인식 0/25)는 **가상의 손** 기준입니다. 실제 카메라에서는
전혀 다른 결과가 나올 수 있습니다.

### 그 밖의 한계


- 규칙 기반 인식은 **근사치**입니다. 실제 수어 사용자가 보면 표준 손 모양이 아닙니다.
  `koreanGestures.ts`의 데이터셋은 **자리 표시자**로 봐주세요.
- **움직임이 있는 수어는 인식하지 못합니다.** 실제 한국수어 단어 대부분이 여기 해당하며,
  시계열 모델로 확장해야 합니다.
- 번역 모드는 한 번에 **한 손만** 분류합니다 (`hands[0]`).
- 브라우저 TTS 음질은 환경에 따라 다릅니다. 긴 문장이 잘리면 짧게 나눠 보세요.
- 조명이 어둡거나 배경이 복잡하면 MediaPipe 추적 자체가 흔들립니다.

기여와 버그 리포트를 환영합니다.
